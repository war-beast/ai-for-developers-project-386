# Спецификация записи на звонок

Правила записи на звонок: типы встреч, окно записи, слоты, бронирование и предстоящие встречи владельца. Источник решений — карта #8; API-контракт — `api/main.tsp` (#16). Правила приняты, контракт фиксируется отдельно и в спецификации не дублируется.

## Роли

- **Владелец** — один заранее заданный профиль из конфигурации. Входа и регистрации нет.
- **Гость** — любой человек без учётной записи. Бронирует слот, не создавая аккаунт.

## Типы встреч

Владелец создаёт тип встречи:

- `id` — slug, который задаёт владелец: `^[a-z0-9]+(-[a-z0-9]+)*$`, 1–64 символа, уникален, неизменяем;
- `title` — от 1 до 100 символов после trim, обязателен;
- `description` — от 0 до 1000 символов, пустое допустимо;
- `durationMinutes` — от 15 до 240, кратно 15.

Доступны создание и список; редактирования и удаления нет. Данные хранятся в памяти процесса и сбрасываются при рестарте.

Ошибки:

- невалидные поля или формат slug — `400 validation_failed` с картой `errors` (поле → список сообщений);
- занятый slug — `409 event_type_exists`;
- неизвестный тип в слотах — `404 event_type_not_found`.

## Окно записи

- Начинается с завтрашнего дня и занимает 14 календарных дней включительно.
- Считается в поясе владельца `Europe/Moscow`.
- Пересчитывается на каждый запрос от текущей даты.
- `windowStart` и `windowEnd` — календарные даты `YYYY-MM-DD`.

## Рабочие часы и слоты

- Рабочие часы: понедельник–пятница, 09:00–18:00 по `Europe/Moscow`. Выходные недоступны.
- Шаг стартов — общий для всех типов, 30 минут; сетка начинается в 09:00.
- Слот валиден, если `start + duration <= 18:00`. Для типа на 45 минут последний старт — 17:00, а не 17:15.
- Тип длиннее 9 часов даёт `200` с пустыми днями, без ошибки.
- В ответе все 14 дней по возрастанию; пустые дни — с `slots: []`.
- Метаданные ответа: `timeZone`, `windowStart`, `windowEnd`, `stepMinutes`.
- Занятые интервалы любых типов исключаются из выдачи.
- Время слотов — ISO-8601 со смещением; смещение берётся для конкретной даты. МСК сейчас фиксирована +03:00.

## Бронирование

Гость отправляет `eventTypeId`, `start`, `guestName`, `guestEmail` и необязательный `comment`.

- `start` должен совпадать со свободным слотом текущего окна.
- Проверка пересечений и вставка выполняются атомарно под блокировкой.
- Пересечение с любой записью отклоняется с `409 slot_taken`. Запись сразу после окончания предыдущей разрешена: после 10:00–11:00 слот 11:00 свободен.
- `start` не из сетки или вне окна — `400 slot_not_available`.
- Неизвестный тип — `404 event_type_not_found`; невалидное тело — `400 validation_failed`.
- Идемпотентности нет: повторная отправка после таймаута даёт `409`.
- `guestEmail` — валидный email до 254 символов; `comment` — до 500.
- `id` записи — GUID строкой; `createdAt` — UTC.
- Ответ `201`: `id`, `eventTypeId`, `eventTypeTitle`, `start`, `end`, `guestName`, `guestEmail`, `comment?`, `createdAt`.

## Предстоящие встречи

Владелец видит в одном списке записи всех типов с `end > сейчас` (включая идущую встречу), отсортированные по возрастанию `start`, без пагинации. Поля те же, что в ответе на создание.

## API

- `GET /api/event-types` — список типов.
- `POST /api/event-types` — создание типа.
- `GET /api/event-types/{eventTypeId}/slots` — свободные слоты на всё окно с метаданными.
- `POST /api/bookings` — создание записи.
- `GET /api/bookings` — предстоящие записи владельца.

Авторизации нет; единый префикс `/api`. Ошибки — `application/problem+json` с `type`, `title`, `status`, `detail`, `code`, `errors?`.

## Интерфейс

- `/` — главная.
- `/book` — карточки типов (название, описание, длительность); пусто — «Пока нет типов встреч».
- `/book/:typeId` — шапка типа, горизонтальная лента 14 дней, сетка слотов выбранного дня; клик по слоту открывает форму гостя на странице.
- Пустой день — «В этот день свободных слотов нет»; пустое окно — «Свободных слотов в ближайшие 14 дней нет».
- `409` — встроенное сообщение «Это время уже занято», слоты перезапрашиваются, день и введённые данные сохраняются, занятый слот снимается с выбора.
- Успех — экран подтверждения с типом, датой/временем и email; ссылки «Записаться ещё» и «На главную».
- `/admin` — список типов и форма создания; ошибки полей из API рядом с полями; пустое состояние.
- `/admin/meetings` — строки «дата/время — тип — гость — контакт — комментарий»; пустое состояние; обновление при возврате на вкладку.
- Навигация: «Записаться», «Админка», «Встречи»; авторизации нет, админские страницы открыты.
- Время везде в поясе владельца с подписью `Europe/Moscow`, формат `3 ноя, 10:00`.

## Тестирование

- **Unit (BLL)**: правила окна, генерации слотов, пересечений и валидации. Проверяемое правило не мокается.
- **Прямые запросы к API**: каждый endpoint на успех и на 400/404/409; smoke-скрипт против запущенного процесса бекенда дергает реальные endpoint'ы, а не только `/health`.
- **Браузерный сценарий на настоящем сервере**: владелец создаёт тип → гость видит его → бронирует слот → владелец видит встречу. Без моков API.
- **UI-компоненты**: только состояния и взаимодействия; бизнес-правила не дублируются.
- Вне границ: нагрузочное тестирование, кросс-браузерная матрица, тесты внешних интеграций.
