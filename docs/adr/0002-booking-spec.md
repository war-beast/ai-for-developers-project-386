# Спецификация записи на звонок

Черновик спецификации поведения основной функциональности: типы встреч, окно записи, слоты, бронирование и предстоящие встречи владельца. Источник решений — карта #8; API-контракт — `api/main.tsp` (#16). Пункты, которые ещё не решены, помечены ссылками на тикеты.

## Роли

- **Владелец** — один заранее заданный профиль из конфигурации. Входа и регистрации нет.
- **Гость** — любой человек без учётной записи. Бронирует слот, не создавая аккаунт.

## Типы встреч

Владелец создаёт тип встречи:

- `id` — slug, который задаёт владелец: `[a-z0-9-]{1,64}`, уникален, неизменяем;
- название;
- описание;
- длительность в минутах.

Доступны создание и список; редактирования и удаления нет. Данные хранятся в памяти процесса и сбрасываются при рестарте. Точные ограничения полей и коды ошибок — #10.

## Окно записи

- Начинается с завтрашнего дня и занимает 14 календарных дней включительно.
- Считается в поясе владельца `Europe/Moscow`.
- Пересчитывается на каждый запрос от текущей даты.

## Рабочие часы и слоты

- Рабочие часы: понедельник–пятница, 09:00–18:00 по `Europe/Moscow`. Выходные недоступны.
- Шаг стартов — общий для всех типов, 30 минут.
- Слот валиден, если интервал `[start, start + duration]` целиком помещается в рабочие часы.
- Слот свободен, если его интервал не пересекается ни с одной записью любого типа.
- Пограничные случаи окна, выходных и последнего старта — #11.

## Бронирование

Гость отправляет тип встречи, время начала, имя, email и необязательный комментарий.

Запись создаётся атомарно: проверка пересечений и вставка выполняются под блокировкой. Пересечение с любой записью отклоняется с `409` и кодом `slot_taken`. Запись сразу после окончания предыдущей разрешена: после 10:00–11:00 слот 11:00 свободен.

Точные правила валидации и ответы на ошибки — #10, #12 и #16.

## Предстоящие встречи

Владелец видит в одном списке предстоящие записи всех типов, отсортированные по возрастанию начала, без пагинации. Правило «предстоящие» и состав полей — #12.

## API

- `GET /api/event-types` — список типов.
- `POST /api/event-types` — создание типа.
- `GET /api/event-types/{id}/slots` — свободные слоты на всё окно с метаданными пояса и шага.
- `POST /api/bookings` — создание записи.
- `GET /api/bookings` — предстоящие записи владельца.

Авторизации нет; единый префикс `/api`. Форма ответов и ошибок фиксируется в TypeSpec-контракте (#16).

## Интерфейс

- `/` — главная.
- `/book` — каталог типов встреч.
- `/book/:typeId` — лента 14 дней и слоты выбранного дня.
- `/admin` — типы встреч и создание.
- `/admin/meetings` — предстоящие встречи.

Состояния, поведение при конфликте и навигация — #15.

## Тестирование

- **Unit (BLL)**: правила окна, генерации слотов, пересечений и валидации. Проверяемое правило не мокается.
- **Прямые запросы к API**: каждый endpoint на успех и на 400/404/409; smoke-скрипт против запущенного процесса бекенда дергает реальные endpoint'ы, а не только `/health`.
- **Браузерный сценарий на настоящем сервере**: владелец создаёт тип → гость видит его → бронирует слот → владелец видит встречу. Без моков API.
- **UI-компоненты**: только состояния и взаимодействия; бизнес-правила не дублируются.
- Вне границ: нагрузочное тестирование, кросс-браузерная матрица, тесты внешних интеграций.
